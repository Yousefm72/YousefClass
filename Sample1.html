١) المطلوب في التصميم نظرة عامة

تم بناء شبكة مؤسسة صغيرة: جميع الأجهزة السلكية تتصل بـ موزّع (Switch) من طراز Cisco افتراضياً، والموزّع يتصل بـ موجّه (Router) عبر رابط Trunk ليمرّر VLANين. شبكة Wi-Fi تخدمها نقطة وصول (Access Point) موصولة بمنفذ في VLAN ثانٍ. عناوين الشبكة من فضاءين خاصّين: 192.168.10.0/24 و 192.168.20.0/24.

٢) رسم تخطيطي مبسّط للربط

الموجّه يفصل الشبكة الداخلية عن الإنترنت؛ الموزّع يقسّم المنافذ إلى VLANين؛ نقطة الواي فاي في VLAN المختبر.

٣) تعيين عناوين الشبكة لكل جهاز

الشرح: كل VLAN له شبكة IP مستقلة؛ عنوان البوابة هو واجهة الموجّه الفرعية لذلك الـ VLAN. القناع 255.255.255.0 يعني /24.

٣-أ) اختيار عنوان ثابت (Static IP) مع نطاق محجوز

الفكرة: تختار نطاقاً من العناوين لا يُستخدم لأي جهاز آخر (مثلاً أجهزة المكاتب من 192.168.10.11 إلى 192.168.10.15، والطابعات .21–.22). يُضبط كل جهاز يدوياً على هذا العنوان، أو تترك هذه العناوين خارج تجمع DHCP كي لا يوزّعها الخادم بالخطأ.

على الموجّه (Cisco IOS) — استثناء النطاق الثابت بالكامل من التأجير عند تفعيل DHCP في نفس الشبكة:

! محجوز للأجهزة الثابتة في VLAN 10 (لا يُؤجَّر عبر DHCP)
ip dhcp excluded-address 192.168.10.11 192.168.10.15
ip dhcp excluded-address 192.168.10.21 192.168.10.22

! مثال VLAN 20 — أجهزة ثابتة من .11 إلى .15 وطابعات .21–.22 و AP على .30
ip dhcp excluded-address 192.168.20.11 192.168.20.15
ip dhcp excluded-address 192.168.20.21 192.168.20.22
ip dhcp excluded-address 192.168.20.30

على جهاز Windows (مثال سطر أوامر — استبدل اسم الواجهة) — تعيين ثابت يطابق الجدول:

netsh interface ip set address name="Ethernet" static 192.168.10.11 255.255.255.0 192.168.10.1
netsh interface ip set dns name="Ethernet" static 8.8.8.8

في الواجهة الرسومية: إعدادات الشبكة ← تعديل خصائص المحول ← IPv4 ← «استخدام عنوان IP التالي» وإدخال العنوان والقناع والبوابة.

٣-ب) اختيار DHCP مع نطاق عناوين التأجير (Lease Range) على الموجّه

الفكرة: الموجّه يوزّع عناوين تلقائياً ضمن الشبكة، لكن نحدد «من وأين» يُؤجَر عبر ip dhcp excluded-address: نستثني البوابة والنطاقات التي نريدها ثابتة أو غير مستخدمة، فيبقى نطاق التأجير الفعلي (مثلاً من .50 إلى .200 فقط).

مثال VLAN 10: تأجير DHCP فقط من 192.168.10.50 إلى 192.168.10.200 — أي استثناء كل ما عدا هذا المدى:

! استثناء: البوابة + كل العناوين قبل .50 + كل العناوين بعد .200
ip dhcp excluded-address 192.168.10.1 192.168.10.49
ip dhcp excluded-address 192.168.10.201 192.168.10.254

ip dhcp pool POOL_OFFICE
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.1
 dns-server 8.8.8.8
exit

مثال VLAN 20: تأجير من 192.168.20.100 إلى 192.168.20.220 (للكمبيوترات والهواتف؛ البوابة والـ AP ثابتان):

ip dhcp excluded-address 192.168.20.1 192.168.20.99
ip dhcp excluded-address 192.168.20.221 192.168.20.254
ip dhcp excluded-address 192.168.20.30

ip dhcp pool POOL_LAB_WIFI
 network 192.168.20.0 255.255.255.0
 default-router 192.168.20.1
 dns-server 8.8.8.8
exit

الأمر ip dhcp excluded-address <أول عنوان> <آخر عنوان> يحدد مجالاً متصلاً من العناوين لا يُمنح عبر DHCP. تجمع ip dhcp pool مع network يعرّف الشبكة؛ النطاق الفعلي للعناوين المؤجرة = الشبكة ناقص كل الأسطر المستثناة. على العميل: IPv4 ← «الحصول على عنوان IP تلقائياً» (DHCP).

٤) تسمية الموزّع (Hostname)

الشرح: الأمر hostname يعطي المبدّل اسماً يظهر في الموجّه ويسهّل التعرف عليه في الشبكات التي فيها أكثر من موزّع. هنا الاسم المختار: SW-YOUSEF-01. 

enable
configure terminal
hostname SW-YOUSEF-01

٥) كلمة مرور صلاحيات التنفيذ المشفّرة (Enable Secret)

الشرح: enable secret تحدد كلمة المرور للدخول إلى وضع التكوين المميز (privileged EXEC). يخزّنها النظام بشكل مشفّر (أقوى من enable password القديم). هذه هي «كلمة المرور المشفّرة» للمستوى الإداري. 

enable secret Yousef_Class_Enable_9

في المختبر الحقيقي استخدم طولاً ومعقّدية أعلى وتغييراً دورياً.

٦) كلمة مرور الموزّع لخط الكونسول وخطوط الاتصال عن بُعد (VTY)

الشرح: «كلمة مرور الموزّع» العادية تُربط عادةً بـ الكونسول (كابل اتصال مباشر) وVTY (جلسات Telnet/SSH). تُدخل عبر password مع login ليطلب الموجّه المصادقة. المثال التعليمي يفصل كلمة كونسول وكلمة جلسات بعيدة. 

line console 0
 password Console_Yousef_2026
 login
 logging synchronous
 exit

line vty 0 4
 password Vty_Yousef_2026
 login
 transport input ssh telnet
 exit

للإنتاج يُفضّل تعطيل Telnet والاكتفاء بـ SSH وتوليد مفاتيح على المبدّل.

٧) إنشاء VLAN افتراضية لكل قسم من الشبكة

الشرح: كل VLAN رقم تعريف (vlan id) واسم وصفي. VLAN 10 للمكاتب، VLAN 20 للمختبر ونقطة الواي فاي. الفصل المنطقي يقلل البرودكاست ويسهّل السياسات والأمان. 

vlan 10
 name OFFICE
exit

vlan 20
 name LAB_WIFI
exit

٨) ربط المنافذ بكل VLAN (Access Ports)

الشرح: المنافذ التي توصل أجهزة طرفية تُضبط access وتُعيَّن لـ VLAN محدد. نطاق Fa0/1–7 لـ VLAN 10، و Fa0/8–15 لـ VLAN 20 (يشمل منفذ نقطة الواي فاي). 

interface range fastEthernet 0/1 - 7
 switchport mode access
 switchport access vlan 10
exit

interface range fastEthernet 0/8 - 15
 switchport mode access
 switchport access vlan 20
exit

٩) منفذ Trunk نحو الموجّه

الشرح: رابط Trunk ينقل أكثر من VLAN على نفس السلك باستخدام tagging (مثل IEEE 802.1Q). الموزّع يرسل إلى الموجّه جميع الـ VLANات المطلوبة على منفذ واحد (هنا Fa0/24). 

interface fastEthernet 0/24
 switchport mode trunk
 switchport trunk allowed vlan 10,20
exit

١٠) إعداد الموجّه — واجهة فرعية لكل VLAN (Router-on-a-Stick)

الشرح: الموجّه يحمل عنوان البوابة لكل شبكة. الواجهة الفعلية gigabitEthernet 0/0 تُقسَّم إلى واجهتين فرعيتين بـ encapsulation dot1Q ليتم فصل حركة VLAN 10 عن VLAN 20. 

hostname R-YOUSEF-01

interface gigabitEthernet 0/0
 no shutdown
exit

interface gigabitEthernet 0/0.10
 encapsulation dot1Q 10
 ip address 192.168.10.1 255.255.255.0
exit

interface gigabitEthernet 0/0.20
 encapsulation dot1Q 20
 ip address 192.168.20.1 255.255.255.0
exit

! مثال واجهة للإنترنت (يختلف حسب مزود الخدمة)
interface gigabitEthernet 0/1
 ip address dhcp
 no shutdown
exit

العناوين في جداول القسم ٣ مُعيّنة يدوياً في هذا المثال. لاستخدام DHCP من الموجّه لتوزيع العناوين تلقائياً (تجمعان لـ VLAN 10 و 20 واستثناءات العناوين) راجع القسم ١٣ في نهاية الصفحة.

١١) شبكة Wi-Fi — الاسم (SSID) وكلمة المرور

الشرح: نقطة الوصول تبثّ شبكة لاسلكية؛ اسم الشبكة هو SSID، وكلمة المرور تُضبط في واجهة الـ AP (أو تُدار مركزياً). العملاء ينضمون إلى نفس VLAN 20 حسب التصميم.

اسم شبكة Wi-Fi (SSID): YousefClass-Net

كلمة مرور Wi-Fi (WPA2/WPA3): NetSecure_Yousef_2026

في الواجهة الحقيقية للـ AP اختر WPA3 أو WPA2-AES، وعطّل WEP والمصادقة المفتوحة.

١٣) استخدام DHCP على الموجّه لتوزيع العناوين والإعدادات تلقائياً

لـ عناوين ثابتة داخل نطاق محجوز وDHCP داخل نطاق تأجير محدد بأوامر excluded-address تفصيلاً، راجع القسم ٣-أ و٣-ب أعلاه.

الشرح: بروتوكول DHCP يوزّع على الأجهزة عنوان IP وقناع الشبكة والبوابة وخادم DNS دون إدخال يدوي. الموجّه (أو خادم DHCP مخصّص) يستجيب بعد تسلسل DORA (Discover، Offer، Request، Ack). عند تفعيل DHCP، تُضبط بطاقة الشبكة في كل كمبيوتر وطابعة تدعم DHCP على «الحصول على عنوان تلقائياً».

نستثني (ip dhcp excluded-address) العناوين التي نريدها ثابتة—مثل بوابة كل VLAN (.1) وعنوان إدارة نقطة الواي فاي (192.168.20.30) إن رغبت ببقائه ثابتاً. باقي الأجهزة يمكن أن تأخذ عناوين من مجال التأجير (مثلاً من .50 إلى .200) أو من الشبكة كاملة بعد الاستثناءات.

مثال تكوين DHCP كامل على الموجّه R-YOUSEF-01 (بعد واجهات VLAN)

! استثناء العناوين المحجوزة (بوابات، خادم، AP إدارة، طابعات إن أردتها ثابتة بالـ Reservation لاحقاً)
ip dhcp excluded-address 192.168.10.1
ip dhcp excluded-address 192.168.10.21 192.168.10.22
ip dhcp excluded-address 192.168.20.1
ip dhcp excluded-address 192.168.20.21 192.168.20.22
ip dhcp excluded-address 192.168.20.30

! تجمع VLAN 10 — المكاتب
ip dhcp pool POOL_OFFICE
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.1
 dns-server 8.8.8.8
exit

! تجمع VLAN 20 — المختبر والأجهزة اللاسلكية خلف الـ AP
ip dhcp pool POOL_LAB_WIFI
 network 192.168.20.0 255.255.255.0
 default-router 192.168.20.1
 dns-server 8.8.8.8
exit

إن أردت أن تأخذ أجهزة الكمبيوتر العناوين من DHCP بدلاً من الجدول اليدوي، أزل استثناءات نطاق الأجهزة (أو لا تستثني إلا البوابة والطابعات إن ثبّتها يدوياً). يمكن حجز عنوان ثابت لجهاز معيّن عبر Reservation بربط عنوان MAC بعنوان IP على الموجّه. للمزيد عن مراحل DHCP راجع صفحة شرح DHCP.

١٤) عزل الضيوف — VLAN ثالث (GUEST) خطوة بخطوة

الهدف: شبكة ضيوف منفصلة 192.168.30.0/24 لا ترى أجهزة المكاتب أو المختبر مباشرة؛ تخرج للإنترنت عبر الموجّه فقط. نفترض منفذ الموزّع Fa0/16 لنقطة وصول ثانية أو كابل يخص الضيوف، ونحدّث الـ Trunk ليشمل VLAN 30.

الخطوة 1 — الموزّع: إنشاء VLAN 30 وتسميتها

configure terminal
vlan 30
 name GUEST
exit

الخطوة 2 — الموزّع: جعل منفذ الضيوف في VLAN 30 (Access)

interface fastEthernet 0/16
 switchport mode access
 switchport access vlan 30
exit

إذا كان منفذ AP يمرّ عبره أكثر من VLAN، استخدم trunk على منفذ الـ AP وعلّم SSID الضيف بـ VLAN 30 من واجهة الـ AP.

الخطوة 3 — الموزّع: تحديث Trunk نحو الموجّه ليشمل 30

interface fastEthernet 0/24
 switchport trunk allowed vlan 10,20,30
exit
end
write memory

الخطوة 4 — الموجّه: واجهة فرعية للضيوف وعنوان البوابة

configure terminal
interface gigabitEthernet 0/0.30
 encapsulation dot1Q 30
 ip address 192.168.30.1 255.255.255.0
 no shutdown
exit

الخطوة 5 — الموجّه: DHCP لتأجير عناوين الضيوف (مثال)

ip dhcp excluded-address 192.168.30.1
ip dhcp pool POOL_GUEST
 network 192.168.30.0 255.255.255.0
 default-router 192.168.30.1
 dns-server 8.8.8.8
exit

الخطوة 6 — شبكة Wi-Fi للضيوف (وصف)

أنشئ SSID منفصلاً مثل YousefClass-Guest واربطه بـ VLAN 30 على نقطة الوصول؛ كلمة مرور مختلفة عن شبكة الموظفين. على العملاء يُضبط الحصول على عنوان تلقائياً (DHCP).

١٥) تقييد الطابعات بقوائم وصول (ACL) — خطوة بخطوة

الهدف: السماح بطباعة من شبكات المكاتب والمختبر فقط على منافذ الطباعة الشائعة، ومنع شبكة الضيوف من الوصول للطابعات، مع منع الطابعات من بدء اتصالات غير ضرورية للخادمات الداخلية أو الإنترنت (حسب سياسة المختبر).

قوائم الوصول على واجهات الموجّه تتحكم في الحركة الممرَّرة عبر التوجيه بين الشبكات. إذا كان الجهاز والطابعة في نفس VLAN دون المرور بالموجّه، فلن تُطبَّق هذه ACL؛ للطباعة من نفس VLAN مع سياسة صارمة يُفضّل VLAN مخصص للطابعات أو إعدادات على الموزّع الطبقي (L3).

الخطوة 1 — تعريف قائمة موسعة: من يصل للطابعات (من الشبكات الموثوقة فقط)

ip access-list extended ACL_TO_PRINTERS
 remark طباعة TCP 9100 و LPD 515 — من المكاتب والمختبر فقط
 permit tcp 192.168.10.0 0.0.0.255 host 192.168.10.21 eq 9100
 permit tcp 192.168.10.0 0.0.0.255 host 192.168.10.22 eq 9100
 permit tcp 192.168.20.0 0.0.0.255 host 192.168.20.21 eq 9100
 permit tcp 192.168.20.0 0.0.0.255 host 192.168.20.22 eq 9100
 permit tcp 192.168.10.0 0.0.0.255 host 192.168.10.21 eq 515
 permit tcp 192.168.20.0 0.0.0.255 host 192.168.20.21 eq 515
 remark منع الضيوف من الوصول لعناوين الطابعات
 deny   ip 192.168.30.0 0.0.0.255 host 192.168.10.21
 deny   ip 192.168.30.0 0.0.0.255 host 192.168.10.22
 deny   ip 192.168.30.0 0.0.0.255 host 192.168.20.21
 deny   ip 192.168.30.0 0.0.0.255 host 192.168.20.22
 permit ip any any

الخطوة 2 — تطبيق القائمة على واجهات VLAN (الاتجاه الوارد للموجّه من كل شبكة)

interface gigabitEthernet 0/0.10
 ip access-group ACL_TO_PRINTERS in
exit
interface gigabitEthernet 0/0.20
 ip access-group ACL_TO_PRINTERS in
exit
interface gigabitEthernet 0/0.30
 ip access-group ACL_TO_PRINTERS in
exit

يمكن تقسيم القوائم لاحقاً إلى قائمة للضيوف وقائمة للموظفين؛ المثال أعلاه موحّد للتوضيح.

الخطوة 3 (اختياري) — تقييد ما «تخرجه» الطابعات من اتصالات للأعلى

ip access-list extended ACL_FROM_PRINTERS
 remark منع الطابعات من تصفّح أنظمة داخلية أو إنترنت — عدّل حسب الحاجة
 deny   ip host 192.168.10.21 any
 deny   ip host 192.168.10.22 any
 deny   ip host 192.168.20.21 any
 deny   ip host 192.168.20.22 any
 permit ip any any

هذا يمنع الطابعات من بدء أي حركة صادرة؛ إذا احتجت تحديثات من الشركة عبر الإنترنت، أضف permit tcp host … eq 443 قبل سطر المنع أو أزل المنع عن الإنترنت.

! تطبيق على واجهة VLAN الذي يمرّ منها الصادر من الطابعات نحو التوجيه (مثال اتجاه out على نفس الشبكة —
! غالباً يُعدَّل التصميم لوضع الطابعات في VLAN طابعات؛ راجع سياسة الشبكة لديك)
interface gigabitEthernet 0/0.10
 ip access-group ACL_FROM_PRINTERS out

تطبيق out على الواجهة الفرعية يعتمد على اتجاه الحزم؛ للتبسيط استخدم في المختبر الخطوة 1–2 أولاً ثم طوّر سياسة الطابعات.

١٦) جدار ناري على الموجّه (Zone-Based Firewall) — خطوة بخطوة

الهدف: فصل مناطق الأمان: الداخلية (المكاتب والمختبر)، الضيوف، والخارج (WAN)، مع فحص حالة الاتصال (inspect) نحو الإنترنت ومنع مرور الضيوف إلى الداخل بشكل حالة-ملزم. الأوامر التالية نموذجية لـ Cisco IOS مع دعم zone security؛ قد تختلف أسماء الصور البرمجية حسب الجهاز.

إذا كانت الواجهات تستخدم مسبقاً ip access-group من القسم ١٥، قد يحدث تعارض؛ في المختبر إما تعطل ACL على الواجهة التي انتقلت إلى منطقة أمنية أو تكتفي بالبديل السريع في أسفل هذا القسم.

الخطوة 1 — تعريف المناطق الأمنية

configure terminal
zone security Z_INSIDE
zone security Z_GUEST
zone security Z_OUTSIDE

الخطوة 2 — ربط الواجهات بالمناطق

interface gigabitEthernet 0/0.10
 zone-member security Z_INSIDE
exit
interface gigabitEthernet 0/0.20
 zone-member security Z_INSIDE
exit
interface gigabitEthernet 0/0.30
 zone-member security Z_GUEST
exit
interface gigabitEthernet 0/1
 zone-member security Z_OUTSIDE
exit

الخطوة 3 — سياسة فحص (inspect) من الداخل والضيوف نحو الخارج

class-map type inspect match-any CM_INSP_PROTOCOLS
 match protocol tcp
 match protocol udp
 match protocol icmp
exit

policy-map type inspect PM_INSIDE_TO_OUT
 class type inspect CM_INSP_PROTOCOLS
  inspect
exit

policy-map type inspect PM_GUEST_TO_OUT
 class type inspect CM_INSP_PROTOCOLS
  inspect
exit

قد تحتاج تعريف parameter-map أو مطابقة بروتوكولات حسب صورة IOS؛ إن فشل match protocol استخدم مطابقة ACL داخل class-map.

الخطوة 4 — منع الضيوف من الوصول للشبكات الداخلية (مع السماح بالإنترنت عبر الفحص)

ip access-list extended ACL_GUEST_BLOCK_INTERNAL
 deny   ip 192.168.30.0 0.0.0.255 192.168.10.0 0.0.0.255
 deny   ip 192.168.30.0 0.0.0.255 192.168.20.0 0.0.0.255
 permit ip 192.168.30.0 0.0.0.255 any
exit

class-map type inspect match-all CM_GUEST_TO_INSIDE
 match access-group name ACL_GUEST_BLOCK_INTERNAL
exit

policy-map type inspect PM_GUEST_TO_INSIDE
 class type inspect CM_GUEST_TO_INSIDE
  drop
 class class-default
  drop
exit

أحياناً يُدمَج المنع داخل zone-pair مع inspect للإنترنت فقط؛ البديل البسيط بدون ZBF هو القسم ١٤ مع ip access-group ACL_GUEST_IN in على Gi0/0.30.

الخطوة 5 — ربط أزواج المناطق (Zone-Pairs) بسياسات الفحص والمنع

zone-pair security ZP_IN_OUT source Z_INSIDE destination Z_OUTSIDE
 service-policy type inspect PM_INSIDE_TO_OUT
exit

zone-pair security ZP_G_OUT source Z_GUEST destination Z_OUTSIDE
 service-policy type inspect PM_GUEST_TO_OUT
exit

zone-pair security ZP_G_IN source Z_GUEST destination Z_INSIDE
 service-policy type inspect PM_GUEST_TO_INSIDE
exit
end
write memory

بديل سريع بدون مناطق (قائمة وصول على واجهة الضيوف)

إن كان جهازك لا يدعم ZBF، استخدم نفس منطق المنع:

ip access-list extended ACL_GUEST_IN
 deny   ip 192.168.30.0 0.0.0.255 192.168.10.0 0.0.0.255
 deny   ip 192.168.30.0 0.0.0.255 192.168.20.0 0.0.0.255
 permit ip 192.168.30.0 0.0.0.255 any
exit

interface gigabitEthernet 0/0.30
 ip access-group ACL_GUEST_IN in

هذا البديل يمنع الضيوف من الوصول للشبكات 10 و 20 لكنه لا يضيف فحصاً حالة-ملزماً (stateful) للإنترنت مثل inspect؛ للإنتاج يُفضّل ZBF أو جدار ناري مخصص.

ختاماً

هذا الملف Sample1.html يجمع بين مخطط العناوين، تقسيم الفيلانات، منافذ الموزّع، وإعدادات أمنية أساسية مع شرح كل خطوة بالعربية، واستخدام DHCP على الموجّه، وتوسّعات أمنية: VLAN ضيوف (القسم ١٤)، قوائم وصول للطابعات (القسم ١٥)، وجدار ناري مبني على المناطق أو بديل ACL (القسم ١٦).
